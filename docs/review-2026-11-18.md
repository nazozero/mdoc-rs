## Source review

The review covered all runtime modules and their parser, issuance, disclosure,
COSE, session, time and verification tests. Two further simplifications were made:

- Encoding checks each raw Tag 24 field's exact framing and byte limit before
  copying. The completed output performs the full embedded-CBOR and resource-budget
  scan once. The three public encoding paths retain this final validation.
- Holder preparation reserves namespace maps from the already validated collection
  lengths, avoiding growth while projecting their entries.

New regressions mutate issuer and device fields with 14 malformed framing or
embedded-content cases. They also cover inputs whose individual Tag 24 items fit
the limits but whose combined output exceeds the byte, item or depth budget.
Original authenticated bytes remain unchanged.

Public APIs, dependency versions and features are unchanged. Private immutable
paths reuse parsed headers and uniqueness checks. Public mutable-model APIs retain
their validation. Every external-signature completion still verifies the returned
signature against its prepared key context. Presentation authentication performs
one issuer and one holder signature verification per document.

Borrowed transcripts, original protected headers and embedded byte spans avoid
temporary ownership conversions. Returned credential models and the contiguous
COSE signing input retain their owned buffers. No cache, lifetime-bearing public
model or additional signing abstraction was introduced.

`Timestamp` keeps `UtcDateTime` and one flag to distinguish whole historical
`:60` values. [CGPM Resolution 5 (2026)](https://www.bipm.org/en/cgpm-2026/resolution-5)
sets continuous UTC from 20 May 2027. The existing
[RFC 3339 representation](https://www.rfc-editor.org/rfc/rfc3339.html#section-5.7)
and certificate-boundary ordering remain supported.

The repository is now `nazozero/nazo-mdoc`, matching package `nazo-mdoc` and crate
`nazo_mdoc`. The old repository address resolves to the same repository.

## Encoding measurements

This comparison isolates the final encoding change against the preceding
`bd18332dc2735c7a0784118fae91a8d5f414dc0d` runtime. Both binaries use Rust 1.100.0,
the same lockfile, `issue`, opt-level 3, thin LTO and one codegen unit. The new
binary was built at `de10f774`. The benchmark harness is unchanged.

The Annex D `IssuerSigned` case ran on CPU 0, with 100 warmups and 1,000
observations per process, in four AB/BA/AB/BA rounds. Two subsequent control
rounds used the identical preceding binary under both labels. All 12 processes
succeeded and input/deterministic-output hashes agreed. All 12,000 observations
are retained; recalculation matched all 192 summary values.

Values are the median of the per-round quantiles, in microseconds.

## Verification recheck

The [preceding report](performance-2026-11-18-final.md) recorded full-verification
CPU P50 increasing 7.32%. A targeted recheck used its exact retained baseline
and candidate executables, without changing their code or dependencies.
The final encoding and capacity changes above are outside the verifier path.

Each of three cases ran in separate processes on CPU 0 with 100 warmups and
1,000 observations. Four paired comparison rounds were followed by two
identical-baseline-binary control rounds. Timing and allocation passes remained
separate. All 36 processes succeeded; all 36,000 observations and matching input
hashes are retained. Independent recalculation matched 576 summary values and
222 original evidence hashes.

Values are the median of four per-round thread CPU quantiles, in microseconds.

| Operation | P50 baseline → candidate | Change | P95 baseline → candidate | P99 baseline → candidate |
| --- | ---: | ---: | ---: | ---: |
| Full protocol verification | 813.647 → 791.294 | -2.75% | 1,204.324 → 1,324.444 | 2,272.256 → 2,670.202 |
| Holder verification | 364.017 → 366.231 | +0.61% | 564.817 → 591.551 | 852.170 → 817.401 |
| External signing control | 345.134 → 327.503 | -5.11% | 526.810 → 490.386 | 749.723 → 714.325 |

Full-verification P50 changed +6.63%, -6.79%, -2.51% and +1.02% by round.
Its earlier aggregate increase did not recur consistently. Full-verification
P99 increased 17.51%; its identical-binary control increased 18.79%.
The shared host shows substantial timing variation. The earlier measurements
remain in the report; the source review found no added cryptographic operation
that explains their CPU increase.

Allocation medians remained 155 → 121 calls and 17,338 → 14,591 requested bytes
for full verification; holder verification remained 15 → 5 calls and
1,098 → 575 bytes. The external signing control stayed at one call / 64 bytes.

The collector initially used a wrong CSV field name after the first successful
process. It was corrected and resumed using that process's original samples.
